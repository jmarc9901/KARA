Why KARA

        
Three ideas, one small language

        
No runtime magic, no hidden frameworks. Just a language that does exactly what it says.

      

      

        

          
🧩

          
Declarative UI

          
Components with props, per-instance state, conditional rendering and lists — expressed in a readable, JSON-like syntax.

        

        

          
⚡

          
Reactive state

          
state + derived ordered by a real dependency graph. Forward references work; cycles are compile errors.

        

        

          
🛡️

          
Real compiler

          
A genuine pipeline — lexer → parser → semantic analysis → static type inference — with readable errors and line/column everywhere.

        

        

          
🛠️

          
Zero-dependency LSP

          
Live diagnostics, type hovers and autocompletion from a hand-rolled language server, consumed by the VS Code extension.

        

        

          
🌐

          
Browser playground

          
Compile, run and debug .kara entirely client-side. No server, no install, no build step — including this page.

        

        

          
🪟

          
Desktop via Tauri

          
A native window shell with hot-reload, and the path to .exe / .app / AppImage.

        

      

    


    

      

        
How it works

        
From zero to a window in three commands

      

      

        

          
Write .kara

          
One file, no config: App { title, size, state, Column { ... } }.

        

        

          
kara dev

          
Compiles, type-checks, starts the runtime and hot-reloads on every save.

        

        

          
Ship desktop

          
Wrap it in a native Tauri window and build installers for the three OSes.
